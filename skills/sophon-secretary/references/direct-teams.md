# ทีมที่ขึ้นตรงกับเลขา (CNT, TRN, DEV)

สามทีมนี้ไม่ใช่งานประมาณราคา จึง **ไม่ผ่านหัวหน้าทีม (chief-engineer)** — เลขาส่งใบสั่งงานเอง ตามงาน ตรวจเบื้องต้น และนำเสนอพี่โสภณตรวจ/อนุมัติ

```
พี่โสภณ ⇄ เลขา ⇄ ทีม Content AI (ai-content-creator)            → เลขาตรวจ → พี่โสภณอนุมัติ → โพสต์ Facebook อัตโนมัติ
              ⇄ ทีมเนื้อหาการอบรม (training-developer)          → พี่โสภณตรวจทุกครั้ง
              ⇄ ทีมเขียนโปรแกรม (web-app-developer,
                                 sketchup-extension-developer) → พี่โสภณตรวจ/อนุมัติ merge
```

| รหัส | ทีม | แฟ้มงาน |
|---|---|---|
| CNT | ทีม Content AI สำหรับงานก่อสร้าง | `JOB/content/<id>/` |
| TRN | ทีมจัดทำเนื้อหาการอบรม | `JOB/training/<รหัสคอร์ส>/` |
| DEV | ทีมเขียนโปรแกรม (เว็บ + SketchUp) | repo/branch ตามใบสั่งงาน + `JOB/dev/report.md` |

ใช้ `office.py init` เปิดแฟ้มงานเหมือนเดิม และ `office.py log JOB CNT|TRN|DEV <สถานะ> "..."` บันทึกเหตุการณ์ (สถานะเพิ่ม: `awaiting_approval`, `approved`, `published`, `rejected`)

## ใบสั่งงาน (เลขาเขียน)
```
ตำแหน่ง: <ทีม> | สั่งโดย: พี่โสภณ (ผ่านเลขา) | SKILL=<path> JOB=<path>
งาน: ... | ผลงานที่ต้องการ: ... | กำหนดส่ง: ...
ข้อมูลประกอบ: JOB/in/... | ข้อห้าม/ข้อกำหนด: ...
```
ทีมต่าง ๆ ทำงานพร้อมกันได้ (เรียกหลาย agent ใน message เดียว, run_in_background)

## CNT — ทีม Content
1. เลขาส่งใบสั่งงาน → CNT ทำโพสต์ตาม `content-and-facebook.md`
2. **เลขาตรวจก่อน** ตาม checklist ใน content-and-facebook.md (เปิดดูภาพทุกภาพ) — ไม่ผ่านส่งกลับพร้อมคอมเมนต์
3. **เสนอพี่โสภณอนุมัติ**: ส่งภาพด้วย SendUserFile (display: render) + แคปชันเต็ม + เวลาโพสต์ แล้วถามด้วย AskUserQuestion ทีละโพสต์ (หรือรวมหลายโพสต์ในคำถามเดียวสูงสุด 4)
   ตัวเลือก: `อนุมัติ โพสต์ตามเวลาที่ตั้ง` / `อนุมัติ โพสต์ทันที` / `แก้ไข` / `ไม่โพสต์`
4. อนุมัติ → `fb_post.py approve` แล้ว `fb_post.py post` (ดูหัวข้อ Facebook) → รายงานลิงก์โพสต์
5. แก้ไข → ส่งคอมเมนต์ให้ CNT → กลับไปข้อ 2 (การแก้ทำให้การอนุมัติเดิมเป็นโมฆะ)

## TRN — ทีมเนื้อหาการอบรม
1. เลขาส่งใบสั่งงาน → TRN ส่ง **โครงร่าง** ก่อน
2. เลขาสรุปโครงร่างให้พี่โสภณตรวจ (ส่งไฟล์ outline.md ด้วย SendUserFile) → อนุมัติ/แก้
3. TRN ทำเนื้อหาเต็ม → เลขาตรวจความครบ (ทุกไฟล์ตาม training-developer มีอยู่จริง เปิดได้ สไลด์ตรงโครงร่าง) → ส่งพี่โสภณตรวจ **ทุกครั้ง** พร้อมสรุป 5–10 บรรทัด
4. แก้ไขวนจนพี่โสภณบอกผ่าน → `office.py log JOB TRN approved "..."`

## DEV — ทีมเขียนโปรแกรม
- งานเว็บ → `web-app-developer`, งาน SketchUp → `sketchup-extension-developer`, งานที่เชื่อมกัน → เรียกทั้งสองพร้อมกันและให้ตกลง `docs/interface.md`
- repo ต้องอยู่ใน session (ถ้าไม่มีให้ใช้ `add_repo` / `list_repos` ก่อน) ระบุ branch ในใบสั่งงาน
- งานใหญ่/กำกวม → ทีมส่ง `PLAN.md` ก่อน เลขานำเสนอพี่โสภณอนุมัติแผน
- ส่งงาน → เลขาตรวจว่ารายงานมีผลทดสอบตามจริง ภาพหน้าจอ ลิงก์ branch/PR → สรุปพี่โสภณ
- **merge, deploy, เผยแพร่ .rbz** ทำเฉพาะเมื่อพี่โสภณสั่งชัดเจนสำหรับงานนั้น

## ปัญหาและการประชุม
ใช้ `meeting-protocol.md` เหมือนทีม QS ได้ทุกทีม รวมถึงข้ามสาย เช่น CNT ขอตัวเลขผลงานจาก BOQ, TRN ขอไฟล์ตัวอย่างจากทีม QS, DEV ขอสเปคฟีเจอร์จาก TRN — ผลรายงานพี่โสภณผ่านเลขา
