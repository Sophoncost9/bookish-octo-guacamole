# ขั้นตอนการทำงานของสำนักงานพี่โสภณ

## 0. สายบังคับบัญชาและการไหลของงาน

```
คำสั่ง:   พี่โสภณ → เลขา → หัวหน้า → (ใบสั่งงาน ส่งโดยเลขา) → ฝ่ายต่าง ๆ
ผลงาน:   ฝ่ายต่าง ๆ → หัวหน้า (ตรวจ/รวม) → เลขา → พี่โสภณ
ปัญหา:   ฝ่ายที่เกี่ยวข้อง ⇄ ประชุมกันเอง (เลขานัดและจดรายงาน) → เลขา → พี่โสภณ
                                                              └→ สำเนาหัวหน้า (ปรับแผน)
```

| รหัส | ฝ่าย | agent | ผลงานหลัก |
|---|---|---|---|
| HEAD | หัวหน้าทีม | `chief-engineer` | แผนงาน ใบสั่งงาน ตรวจงาน สรุปส่งมอบ |
| STR | วิศวกรโครงสร้าง | `structural-engineer` | ปริมาณงานโครงสร้าง + Backup |
| ARC | วิศวกรถอดแบบสถาปัตย์ | `architectural-qs-engineer` | ปริมาณงานสถาปัตย์ + Backup |
| MEP | วิศวกรถอดแบบงานระบบ | `mep-qs-engineer` | ปริมาณงานไฟฟ้า ประปา-สุขาภิบาล แอร์ (+ดับเพลิงถ้ามี) |
| PUR | ฝ่ายจัดซื้อ | `purchasing-officer` | ราคาวัสดุ+ค่าแรงต่อหน่วย พร้อมแหล่งอ้างอิง |
| BOQ | ทีม BOQ และ Presentation | `boq-presentation-team` | BOQ Excel, สรุปราคา, เอกสาร/สไลด์นำเสนอ |
| PLN | ทีมวางแผนงานก่อสร้าง | `construction-planner` | WBS, Gantt, S-Curve, งวดงาน, แผนจัดซื้อ |

## 1. รับคำสั่ง (เลขา)
- ทวนคำสั่งกลับเป็นข้อ ๆ ให้พี่โสภณเห็นในข้อความเดียว
- ข้อมูลขั้นต่ำ: ชื่องาน/โครงการ, ไฟล์แบบ/Spec (path หรือลิงก์), ผลงานที่ต้องการ, กำหนดส่ง, ข้อกำหนดพิเศษ (ราคาบริษัท, Vendor List, แบบฟอร์ม BOQ, วันเริ่มงาน, จำนวนงวด)
- ขาดข้อไหนที่เดาไม่ได้ → ถาม 1 ครั้ง รวมทุกคำถาม ข้อที่มีค่ามาตรฐานให้ใช้ค่ามาตรฐานและแจ้งไว้
- ถ้าพี่โสภณสั่งงานเล็ก (เช่น "เช็คราคาเหล็ก DB12 ให้หน่อย") ไม่ต้องเปิดทุกฝ่าย — ยังต้องผ่านหัวหน้า แต่หัวหน้าจะสั่งเฉพาะฝ่ายที่เกี่ยวข้อง

## 2. เปิดแฟ้มงาน (เลขา)
```bash
python SKILL/scripts/office.py init JOB "ชื่องาน"
```
สร้างโครงตาม handoff.md แล้วเขียน `JOB/00_order.md`:

```markdown
- งานที่สั่ง: ...
- ไฟล์ต้นฉบับ: in/...
- ผลงานที่ต้องการ: ...
- กำหนดส่ง: ...
- ค่าที่ใช้แทนเพราะไม่ได้ระบุ: ...
## คำสั่งเพิ่มเติม
```

## 3. หัวหน้าวางแผน (โหมด PLAN)
เลขาเรียก `chief-engineer` ด้วยใบสั่ง:
```
โหมด: PLAN
SKILL=<path เต็มของ skill> JOB=<path เต็มของแฟ้มงาน>
อ่าน JOB/00_order.md และไฟล์ใน JOB/in/ แล้วเขียน JOB/01_plan.json ตาม SKILL/references/handoff.md
```
หัวหน้าส่งกลับ: สรุปแผน + `01_plan.json` (wave, ใบสั่งงานของแต่ละฝ่ายแบบพร้อมส่ง)

## 4. ส่งใบสั่งงานตาม wave (เลขา)
wave มาตรฐาน (หัวหน้าปรับได้):

| wave | ฝ่ายที่ทำพร้อมกัน | รอจาก |
|---|---|---|
| A | STR, ARC, MEP (ถอดปริมาณ) + PLN (ร่าง WBS/ลำดับงานจากแบบ) | — |
| B | PUR (สืบราคาทุกคีย์ราคา) + PLN (คำนวณระยะเวลาจากปริมาณ) | ปริมาณจาก wave A ผ่านการตรวจ |
| C | BOQ (BOQ Excel + Presentation รวมแผนงานของ PLN) | ราคาและแผนงาน wave B ผ่านการตรวจ |

- ส่ง `brief` ของแต่ละฝ่ายจาก `01_plan.json` **คำต่อคำ** เติมเฉพาะบรรทัดหัว:
  `ตำแหน่ง: <ชื่อฝ่าย> | สั่งโดย: หัวหน้าทีม (ส่งผ่านเลขา) | SKILL=... | JOB=...`
- ฝ่ายใน wave เดียวกันเรียกพร้อมกันใน message เดียว ใช้ `run_in_background: true`
- ระหว่างรอ รายงานพี่โสภณ 1 บรรทัด เช่น "ตอนนี้ฝ่ายโครงสร้าง สถาปัตย์ งานระบบ กำลังถอดแบบพร้อมกันค่ะ"
- บันทึกเหตุการณ์: `python SKILL/scripts/office.py log JOB <ฝ่าย> <สถานะ> "<ข้อความ>"`

## 5. จัดการปัญหา (เลขา + ฝ่ายที่เกี่ยวข้อง)
หลังแต่ละฝ่ายส่งงาน อ่าน `teams/<ฝ่าย>/report.md` หัวข้อ "ปัญหา":
- ปัญหาภายในฝ่ายเดียวที่ฝ่ายแก้แล้ว → บันทึกใน `issues.md` สถานะ "แก้แล้ว (ภายในฝ่าย)"
- ปัญหาที่เกี่ยวกับฝ่ายอื่น (`need_meeting: yes`) → จัดประชุมตาม `meeting-protocol.md`
- ปัญหาที่ต้องพี่โสภณตัดสิน → รวบรวมถามพี่โสภณทีเดียว ไม่ถามทีละข้อ ระหว่างรอให้ทีมทำงานส่วนอื่นต่อด้วยสมมติฐานที่ระบุไว้

## 6. หัวหน้าตรวจงาน (โหมด REVIEW)
จบแต่ละ wave เรียก `chief-engineer`:
```
โหมด: REVIEW | wave: A | SKILL=... JOB=...
ตรวจ teams/STR, teams/ARC, teams/MEP และรายงานการประชุม meetings/ ที่เกี่ยวข้อง
เขียนผลตรวจลง JOB/reviews/wave-A.md
```
- ผ่าน → wave ถัดไป
- ไม่ผ่าน → หัวหน้าเขียนคอมเมนต์ราย ฝ่าย เลขาส่งกลับฝ่ายนั้น (SendMessage ถ้า agent ยังอยู่ ไม่งั้นเรียกใหม่พร้อมคอมเมนต์) สูงสุด 2 รอบ เกินนั้นหัวหน้าระบุข้อจำกัดในสรุปส่งมอบ

## 7. หัวหน้าสรุปส่งมอบ (โหมด HANDOVER)
หัวหน้าเขียน `JOB/90_head_summary.md`: ผลงานทั้งหมด ตัวเลขสำคัญ (มูลค่ารวม แยกหมวด ระยะเวลา จำนวนงวด) สมมติฐาน ความเสี่ยง และสรุปปัญหา/มติที่ประชุม

## 8. เลขารายงานพี่โสภณ
เขียน `JOB/99_report_to_sophon.md` แล้วสรุปในแชต:
```markdown
# รายงานพี่โสภณ: <ชื่องาน>  (<วันที่>)
## สรุป 3 บรรทัด
- มูลค่างานรวม ... บาท (รวม/ไม่รวม VAT) | ระยะเวลา ... วัน | ... งวด
## ผลงานที่ส่ง
| ผลงาน | ไฟล์ | ผู้จัดทำ | ตรวจโดย |
## ปัญหาที่พบและวิธีแก้ (จากที่ประชุมทีม)
| # | ปัญหา | ฝ่ายที่ร่วมประชุม | มติ/วิธีแก้ | ผลกระทบต่อราคา/เวลา |
## เรื่องที่รอพี่โสภณตัดสิน
1. ... (ตัวเลือก ก/ข พร้อมผลกระทบ และข้อเสนอของทีม)
## สมมติฐานที่ใช้
```
ข้อความในแชต: ไม่เกิน ~15 บรรทัด + path ไฟล์หลัก ถ้าผลงานควรแชร์ต่อ เสนอทำเป็นหน้า Artifact 1 บรรทัด

## 9. งานแก้ไขหลังส่งมอบ (โหมด CHANGE)
พี่โสภณสั่งแก้ → เลขาเพิ่มใน "คำสั่งเพิ่มเติม" ของ 00_order.md → หัวหน้า (CHANGE) บอกฝ่ายที่ต้องแก้และ wave ที่ต้องทำซ้ำ → ทำข้อ 4–8 เฉพาะส่วนนั้น → รายงานเฉพาะสิ่งที่เปลี่ยน (ก่อน/หลัง)
